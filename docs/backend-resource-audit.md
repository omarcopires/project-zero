# Original resource and native-contract audit

**Historical static audit, September 17, 2026.** This inventory preceded the new engine implementation. The original resource set contained QML/JavaScript presentation logic and metadata referring to native runtime services, but no native engine or server implementation was found in the inspected workspace at that time. The later engine in `client/src/` changes that historical situation; consult the [README](../README.md) for current status.

The initial inventory, excluding `.git/`, counted 4,509 original files: one under `data/`, 1,061 under `images/`, 424 under `qt/`, 3,018 under `qt-project.org/`, one under `qtwebchannel/`, two under `spells/`, and two at the then-root (`.clang-format` and `message.txt`). It included 886 QML, three JavaScript, and seven JSON files. Some QML belongs to bundled Qt controls rather than the game. `message.txt` contains QML related to Exaltation Forge. These protected trees are now under `things/` in this repository and must not be edited.

Qt module descriptors referenced Qt 6 plugins, including Qt WebEngine and local `qmlcomponents`/legacy controls. Descriptor names such as `plugin`, `classname`, and `typeinfo` are metadata, not C++ implementations or proof that native types are optional. QML consumers required `WorldMap`, `LightMap`, `mapWindowController`, appearance models, helpers, and image providers. The audit did not establish the original C++ signatures. `qtwebchannel/qwebchannel.js` implements JavaScript proxies, not game authentication. Spell and tutorial JSON files are presentation data, not authoritative server rules. The audit did not open tutorial dumps.

Resource mapping needed explicit attention: `clientwindow.qml` imports `qrc:/qt/qml/qmlcomponents/qml`; module descriptors contain `prefer` paths; some literal `/images/...` and `/fonts/...` URLs do not match physical locations; tutorial content uses `qrc:/tutorial/...`; and `image://...` URLs require providers. New manifests, aliases, and adapters may resolve these contracts without changing original files or substituting modified copies.

At this historical point, the inspected patterns did not find native source/binaries, `.qmltypes`, `.qrc`/`.rcc`, CMake/qmake/Visual Studio projects, or complete world-sprite metadata in the original resource set. That was limited to the inspected workspace and patterns, not Git history, ignored files, or external installations. Assets were supplied later under `things/assets/`; see [asset verification](phase0-assets-verification.md). The audit did not prove runtime loading, rendering fidelity, or 15.25 compatibility. SHA-256 comparisons covered only the review interval and were not write protection.
