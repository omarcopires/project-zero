# Initial world-map rendering

The `qmlcomponents` module registers `WorldMap` and `LightMap`. `WorldMapItem` draws static objects from an injected `MapDescription`. It does not yet compose floors, layers, patterns, animation, lighting, or map commands. `LightMapItem` remains transparent without light data.

The host loads the original `clientwindow.qml`, places `gamewindow.qml` in its placeholder, and injects a presentation controller. Original login and character selection use the connected authentication/session services. `WorldMapItem` receives the initial description after confirmed world entry; the UI does not switch to `INGAME` before decoding. Original QML and images remain unchanged. The local `QtQuick.LegacyControls` module supplies compatibility pieces such as `AbstractStyle`, `LegacyPadding`, `WheelArea`, and `RangeModel`, with `SelectionMode` registered in C++.

QML adapters exist for `AppearanceInstanceRenderer`, `ObjectAppearanceInstance`, `OutfitAppearanceInstance`, `SingleObjectAppearanceInstanceRenderer`, `Lenshelp`, `NumericalEffectOverlay`, `SpeechBubbleOverlay`, `TibiaTargetSelection`, `CachedOutlineText`, and `TibiaTutorialMarker`. Appearance renderers show only static single-sprite objects. Several other adapters preserve the required structure/API without implementing the original private behavior. `CachedOutlineText` uses Qt Quick `Text` without a specialized cache.

`RenderDriver` exposes the selected Qt Quick backend. A provider scales 1-pixel nine-slice frames, resource configuration aliases literal `/images/...` paths to existing `things/images` files, and `TibiaEnums` exposes supported resize and antialiasing modes. UI caching is disabled and the cursor controller is absent. `TooltipHelper` tracks mouse interaction for QML tooltips. `SoundHelper` exposes action names, but `playSound` returns `false` until an audio backend and sound-ID mapping exist. Matching asset IDs to the server remains pending. See [login integration](game-login-integration.md).
